# 聊天室与 GitHub 跨平台连续任务设计（待审阅）

## 目标

以当前多人聊天室作为 IM 入口，让用户在聊天室提出问题，并在与该问题关联的 GitHub Pull Request 中继续讨论、调整方案。系统用同一个可追踪任务保存目标、来源、进展、决策和结果；用户不必手动搬运不同平台的上下文。仍允许多人各自拥有独立任务与会话。

## 用户可见行为

1. 用户在聊天室明确请求，或启用主动协助后被识别出需要处理的问题；智能体创建带来源消息、发起人和仓库范围的任务。
2. 工作区中实现并验证变更后，智能体可以为该任务创建草稿 PR；PR 地址和状态显示在任务卡片，并在聊天室反馈。
3. 已关联 PR 的新评论、代码行评论和审查意见被接收后，系统关联到同一任务，按可信来源和权限检查后作为新指令或反馈处理。执行前读取任务现有决策、PR 当前状态和相关评论；新决策与旧决策冲突时保留历史并采用明确的新方向。
4. 更新同一个 PR 分支后，在原评论或 PR 下反馈进展，同时把摘要同步给发起聊天室。完成或合并状态可在聊天室查看。
5. 普通闲聊和不相关仓库的评论不触发任务；模糊或与现有任务冲突且无法判定的意见标记为待澄清，不能自行猜测。

## 系统边界

- 聊天室沿用现有成员身份、消息和任务系统。人工 @、现有主动识别与跨平台处理共享任务入口；主动识别默认关闭。
- 新增统一工作项：持久化任务 ID、拥有者、聊天室来源、授权仓库、关联 PR/分支、状态、版本、决策记录及事件游标。任务内部的模型会话可独立创建或恢复，但不作为跨平台身份。
- 每个项目独立配置授权仓库和设计维护者；同时允许 GitHub 确认仍有该仓库权限的受邀协作者。仅有其他仓库权限或普通公开评论不构成授权。GitHub 适配器通过配置的 GitHub App 或受限凭据访问授权仓库；第一版本地运行采用轮询接收已关联 PR 的普通评论、审查和行内评论，并读取 PR 的开放、合并和关闭状态。未来可增加 Webhook，事件格式与核心逻辑保持一致。
- 每个 GitHub 事件保存稳定事件 ID、来源、时间、作者、目标任务和处理状态；重复投递不会重复执行或重复回复。启动后从已保存位置补齐事件；周期性检查状态，支持失败重试和限速。
- 一项工作使用唯一的隔离工作区和受控分支。提交前重新读取远程状态和已有变更，检测用户或队友并发修改；遇到冲突、权限不足或不明确的基线时暂停该任务并清楚报告，不覆盖他人的工作。
- 默认使用草稿 PR。对已有 PR 的修订只能作用于该任务关联的分支，必须经过配置的仓库及权限检查。具体代码读写遵循现有工具开关；不自动合并、强制推送或修改未授权仓库。
- GitHub 的外部评论与群消息属于不可信内容，不得因评论内容放宽权限、泄露密钥或读取其他成员的私聊。是否将私聊作为任务上下文必须由用户明确发起；群内和 GitHub 只能看到允许公开的内容。凭据仅在服务端配置，不在日志或页面显示。

## 关键关联与决策

- 不靠标题或模型猜测绑定：创建 PR 时保存仓库全名和 PR 编号；已有 PR 需由用户在任务中明确提供并绑定。
- PR 意见先做来源和事件类型过滤，再用已有任务、同一 PR 的上下文及受限的近期消息判断是否需要行动；只把与该任务相关的意见纳入。事件作为数据，不能改变系统权限。
- 决策记录包含原文引用、作者、来源链接、时间、目标对象、当前生效版本及被替代关系。用户由 A 改为 B 时任务执行采用 B；若新意见含糊、来自非项目设计维护者或未授权协作者或与并发工作冲突，呈现待处理状态。
- 任务结果和状态从统一状态生成，各平台消息包含同一任务及 PR 链接。模型上下文有界：先提供当前目标和最新有效决策，再按需检索来源；不能承诺模型记住无限历史。

## 自动识别问题并提交 PR

主动协助启用后，系统可从公开群聊识别具体、可复现或可定位的问题，创建与来源消息关联的任务；普通闲聊不发言。后台先在隔离工作区只读调查，复现条件或授权不足时向群里说明，不伪称已修复。允许写入时，修改、验证并创建草稿 PR，再报告具体结果及未验证部分。不同成员的任务可并行，任务与会话、权限及结果不得串线。自动运行可能产生模型与 GitHub API 调用，应在管理界面明确显示开启状态及消耗。

## 验证与完成条件

- 使用模拟 GitHub 事件和临时 SQLite 仓库测试任务关联、跨平台 A→B 决策更新、重复事件去重、重启恢复、无关 PR 过滤、乱序事件及权限拒绝。
- 用临时 Git 仓库与模拟适配器测试草稿 PR 创建、同一分支修订、并发改动冲突、执行失败与结果回传；不能把模拟结果说成真实 GitHub 成功。
- 多人同时提交不同任务，验证上下文、任务和回复不串线；PR 意见可推进关联任务且不会读取他人私聊。
- 真实联调分别确认 GitHub 连接、评论读取、受控仓库写入、PR 创建/更新和聊天室反馈；未配置或没有权限时清楚展示状态，不能虚构成功。实际改动外部仓库或发送评论仅在任务已明确授权的范围内执行。
