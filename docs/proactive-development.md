# 本机主动能力实施记录

基线：`5b946cde211a4f719e919780f84ecc9b7c1c4c0d`。本地开发分支：`feat/local-proactive-agent`。

## 交付范围

- 稳定成员会话、工具访问隔离、明确的任务补充及可靠收尾。
- 本地 SQLite 保存消息、任务、计划、缓存、通知；后台任务不抢占用户请求。
- 静默报错预处理、任务异常监控、固定窗口定时摘要，分别开关控制。
- Windows 本机开发；Radmin 仅提供显式监听入口，不自动调整防火墙。
- Harness 可选，后台任务始终不使用 Harness；模拟验收与真实服务验收分别记录。

## 验收约定

权限不能跨私聊；独立请求不能串入其他任务；补充不能在收尾时丢失；只读任务不能修改源码。
普通聊天和智能体输出不触发预处理；相同事件合并去重；源文件变化使缓存失效。
正常心跳不调用模型、不刷通知；用户停止后不重试；进程终止与页面状态一致。
摘要空窗口不调用模型；固定窗口不漏消息；重启合并漏跑；通知按 ID 去重并支持离线恢复。
后台并发最多 1、用户请求优先；预算和功能开关在服务端强制执行。

## 自查修复

- 补充消息可靠接收与最终轮检查，避免 Worker 完成时丢失补充。
- 身份与连接分离，同一成员可以有多个连接，退出一个连接不影响其他连接。
- 待重试的后台任务同样提供停止入口，取消状态保存后不会重新排队。
- 摘要事务失败时，内存中的窗口也不提前推进，避免数据库与调度状态不一致。
- Radmin 模式同时保留仅本机管理入口，队友入口使用邀请码。

## 验证边界

- 本轮不调用真实模型，演示输出与测试替身不能证明模型效果。
- 模拟 Harness 验证执行适配和收尾逻辑；Windows 实际父子进程测试不等同于真实 Harness 权限验收。
- 双地址测试全部位于回环地址，不等同于 Radmin 跨设备和防火墙验证；未改变防火墙或对外发布。
- 单房间、单服务进程；睡眠和关机期间不执行，恢复后补摘要。
- 不做用户写入任务的自动重放。清除浏览器会话后的账号找回、公网部署和跨项目权限模型未实现。
- 摘要采用有界输入；超量消息明确标为覆盖不足。后台调度给用户请求优先入场，但不强制中断已经运行的模型请求。

## 最小验收操作

1. 运行启动脚本，从本机地址加入，确认三项主动规则默认关闭。
2. 启用静默预处理和定时摘要；发送带 `【验收样例】` 标记的异常堆栈，例如引用 `backend/main.py` 的 `ValueError`。
3. 等待约 10 秒，“已准备”出现标注演示的卡片；群聊没有自动分析回复。
4. 点击“生成当前摘要”，侧栏出现摘要和一个通知；刷新页面后能恢复。
5. 结束验收时关闭规则。实际试运行再按需要启用，并保持主机开机。
